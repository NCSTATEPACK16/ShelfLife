# Phase 1.6 — Shoppers: design notes

Condensed vs. the 1.4/1.5 plans (effort budget) — decisions recorded here, executed directly with
TDD per module, same rigor, less ceremony.

**Gate (PLAN.md §16):** a shopper walks in, fills a correct list, pays, leaves; golden test locked.
**Deliverable:** household model, pantry depletion, lists, agent FSM, satisfaction, impulse via path
exposure.

## Scope cuts (explicit, so later phases know what's deferred)

- `satisfaction` terms `queuePenalty`, `spoiledEncounters`, `staffInteraction`, `cleanliness` are
  wired as `0` — their owning systems (checkout/staff = 1.8, spoilage = 1.7) don't exist yet. Only
  `fillRate` and `discovery` (impulse-driven) are live this phase.
- "Pays" emits a `saleCompleted` sim event with the cart total; no ledger/P&L (that's 1.9).
- No trip scheduling/cadence system. Trips are spawned by an explicit `spawnShopper` command (test
  and, later, a scheduler call it) rather than households autonomously deciding to go shopping — the
  gate only requires one deterministic trip, not a scheduler.
- Household segments (§5.1's PriceHunter/Convenience/etc.) are not modeled — one generic household
  type. Segment-driven behavior belongs to store-choice (§5.1), which is M2 (multi-store) territory.
- §12.1's tell table is authored **in full** (all satisfaction + impulse terms) and CI-validated now,
  because that's a content-authoring task independent of which mechanics are live — but only the
  `fillRateMiss` and `discovery`/`impulsePurchase` tells get an actual on-screen bubble this phase;
  the rest exist in content only, ready for their owning phase to wire up.

## Content

- `content/goods/catalog.json` (Zod-validated, same pattern as `fixtures/catalog.json`): `id`, `name`,
  `unitPrice`, `depletionPerDay` (0–1 fraction of pantry consumed per sim day), `reorderThreshold`
  (0–1), `impulseBase` (0–1).
- `content/design/gentle-surface.json5` (Zod-validated): one entry per §5.3/§5.4 term — `term`,
  `bubble`/`animation`/`particle` (string or null), `worldMark` (boolean), `threshold` (number).
  `tools/check-gentle-surface.mjs` fails CI if any term from a fixed required-term list is missing —
  wired into `npm run verify` as `check:content`.

## Sim

- `src/sim/systems/goods/`: `catalog.ts` (parse+load), `types.ts`. Mirrors `systems/grid/catalog.ts`.
- `src/sim/systems/shoppers/`: `types.ts` (`Household`, `Shopper`, FSM states), `household.ts` (pure:
  `advancePantryDay`, `deriveShoppingList`), `system.ts` (`ShoppersSystem`).
- `ShoppersSystem` owns `BuildGrid` + `PathingSystem` references (same ownership pattern
  `PathingSystem` uses for `BuildGrid`). New commands: `addHousehold`, `stockFixture`, `spawnShopper`.
  `stockFixture` registers/updates a `good:<id>` pathing destination from every fixture instance
  currently stocked with that good. A fixed `register` destination is registered once at
  construction from placed `register` fixtures; a fixed `exit` destination is the grid's boundary
  corner (same convention `mountBuildMode`'s debug destination already uses).
- Shopper FSM: `entering → shopping → checkingOut → leaving → done`. In `shopping`, target =
  `good:<list[0]>`; steer via `computeSteering` + `pathing.directionAt/distanceAt`; "arrived" when
  within 1 cell of a non-walkable destination (shelf/register — can't stand inside a fixture) or
  within `arrivalRadius` of a walkable one (the exit). On arrival at a shelf: pop the item into the
  cart, roll impulse (RNG stream `'impulse'`, already reserved in `STREAM_NAMES`) against every other
  stocked good whose destination cells are within a fixed exposure radius of the shopper's position —
  this is "path exposure" (§5.4): only goods actually walked near roll, not the whole store.
- `update(world)`: on a sim-day boundary (`world.tick % TICKS_PER_SIM_DAY === 0`), advance every
  household's pantry one day and recompute its list. Steps every active shopper's FSM once.
- `hash()`: households (sorted by id: pantry values, list), stocking map (sorted by instanceId),
  active shoppers (sorted by id: position, state, list, cart) — everything that affects future
  behavior. Not the pathing fields themselves (already covered by `PathingSystem`'s own hash of its
  destination set, per 1.5's precedent).
- Golden-test-locked: a scenario with one household, one stocked shelf, a register, `spawnShopper`,
  run to completion, hash sampled throughout.

## View (minimal, placeholder-art — matches M1's "playable in placeholder art" scope)

- A small text/icon "bubble" rendered above the shopper sprite (a colored circle placeholder, per
  the existing fixture-rectangle convention) for `fillRateMiss` (shown while a list item's shelf is
  unreachable/absent — deferred if no such case arises this phase) and `discovery`
  (impulse fired) — reusing `content/design/tokens.json` colors, no hardcoded hex.
- Shoppers render as small circles (token-colored) walking the flow field — same placeholder-art
  posture `BuildScene` already uses for fixtures.

## Explicitly out of scope, deferred to later phases

Trip scheduling/cadence, segments, real checkout queues (1.8), spoilage (1.7), staff (1.8), finance
ledger (1.9), full art/animation for tells (M2 art pass).
